# program_sp1 — 백엔드/프런트엔드 골격

새 앱을 시작할 때 이 골격으로 시작한다. 빈 폴더에서 출발하면 매번 같은 함정에
다시 빠지므로, 이미 겪은 것들을 미리 막아 둔 상태에서 시작한다.

## 만들기

```bash
python3 .claude/skills/program_sp1/new_project.py <경로> --name "표시 이름"
cd <경로> && pip install -r requirements.txt && pytest && ./run.sh
```

`--name` 은 화면·문서에 보이는 이름이고, 여기서 파일 이름(`{{SLUG}}`)과 환경변수
접두사(`{{ENV}}_DB` 등)를 만든다. 한글 이름이면 접두사가 `APP_` 이 되니, 여러 앱을
같이 돌릴 거면 `--name` 을 영문으로 주거나 만든 뒤 `config.py` 에서 고친다.

## 구조와 그 이유

| | |
|---|---|
| `backend/logic.py` | **순수 계산. 외부 의존성 0.** 프레임워크도 DB 도 파일도 안 들어온다 |
| `backend/store.py` | 저장 (SQLite 한 칸에 통째로) |
| `backend/config.py` | 설정. **부를 때마다** 환경변수에서 읽는다 |
| `backend/app.py` | HTTP 층. 받고 → 부르고 → 돌려주기만 |
| `frontend/index.html` | 화면 한 장. 서버가 준 것만 그린다 |
| `tests/` | `test_logic` 규칙 · `test_api` 라우트/저장 · `test_ui` 실제 브라우저 |

규칙을 `logic.py` 한 곳에 모으면 테스트가 서버를 안 띄우고 바로 부를 수 있고,
규칙이 바뀔 때 고칠 곳이 하나고, 화면과 API 가 서로 다른 숫자를 말하지 않는다.
라우트 안에 계산을 적기 시작하면 이 셋이 다 무너진다.

## 골격이 미리 막아 둔 함정

전부 실제로 겪고 고친 것들이다. 새 프로젝트에서 이 구조를 유지하는 한 다시 안 겪는다.

**설정을 모듈 최상단에서 읽지 않는다.** 파이썬은 같은 모듈을 두 번 임포트해도
처음 것을 돌려주므로, 전역에 박아 두면 나중에 환경변수를 바꿔도 옛 값이 살아남는다.
파일 하나만 돌리면 통과하고 전체를 돌리면 깨지는 테스트가 이래서 생긴다.

**기본값이 있는 `Form()` 인자는 타입으로 거른다.** `Form(...)` 의 기본값은 HTTP 로
올 때만 채워진다. 파이썬에서 함수를 직접 부르면(테스트가 그렇게 한다) 기본값 자리에
`FieldInfo` 객체가 그대로 들어와 `.split()` 에서 터진다. `isinstance(x, str)` 로 건다.

**FastAPI 는 빈 폼 문자열을 `None` 으로 바꾼다.** 그래서 ""(지움)과 '안 보냄'이
구분되지 않는다. 값을 지우게 하려면 프런트에서 공백 한 칸 같은 빈 문자열이 아닌
값을 보내고 서버에서 `strip()` 한다.

**테스트마다 상태를 되돌린다.** `tests/conftest.py` 가 환경변수와 메모리 상태를 매번
초기화한다. 앞 테스트가 남긴 것 때문에 순서를 바꿀 때만 깨지는 일을 막는다.

**`sys.modules` 를 갈아 끼우지 않는다.** 재시작을 흉내 낼 때 모듈을 바꿔 치우면,
테스트 파일이 맨 위에서 가져온 함수는 옛 모듈을 conftest 는 새 모듈을 보게 돼
상태가 두 벌로 갈린다. 대신 메모리를 비우고 `_restore()` 를 다시 부른다.

**순서를 매번 섞는다.** `pytest-randomly` 가 기본이라 격리가 깨지면 바로 드러난다.
고정 순서로 돌리려면 `pytest -p no:randomly`.

**화면은 브라우저로 확인한다.** 파이썬 테스트는 스크립트가 죽어도, CSS 가 글자를
가려도, 버튼이 아무 일도 안 해도 전부 통과한다. `tests/test_ui.py` 가 실제 Chromium 을
띄운다. 크로미움이 없으면 알아서 건너뛴다.

**워커는 하나만.** 상태를 메모리에 들고 있어서 여럿이면 서로 다른 메모리를 보고
덮어쓴다. 여러 워커가 필요해지면 그때 상태를 DB 로 완전히 내린다.

## 골격을 채울 때

1. `backend/logic.py` 의 `Item` / `summarize` 를 이 앱의 것으로 바꾸고, 규칙마다
   `tests/test_logic.py` 에 테스트를 붙인다 — 서버 없이 도는 이 층이 제일 싸다.
2. `backend/app.py` 의 라우트를 바꾼다. 계산은 여기 적지 말고 `logic.py` 를 부른다.
3. `frontend/index.html` 을 바꾼다. 개수·합계 같은 값은 서버가 준 것을 쓰고 화면에서
   다시 세지 않는다.
4. 화면을 바꿨으면 `tests/test_ui.py` 에 한 줄이라도 추가한다.
5. 커밋 전에 `pytest` 를 두어 번 돌린다 — 순서가 매번 달라서 격리 문제가 드러난다.

주석과 커밋 메시지는 **무엇을 했는지가 아니라 왜 그렇게 했는지**를 적는다. 무엇을
했는지는 diff 에 이미 있다.
