# {{NAME}}

```
pip install -r requirements.txt
./run.sh                 # 윈도우는 run.bat  →  http://127.0.0.1:8000
pytest                   # 순서를 매번 섞어서 돈다
```

## 구조

| | |
|---|---|
| `backend/logic.py` | 순수 계산. **외부 의존성 0** — 프레임워크도 DB 도 안 들어온다 |
| `backend/store.py` | 저장 (SQLite 한 칸에 통째로) |
| `backend/config.py` | 설정. 값을 **부를 때마다** 환경변수에서 읽는다 |
| `backend/app.py` | HTTP 층. 받고 → 부르고 → 돌려주기만 |
| `frontend/index.html` | 화면 한 장. 서버가 준 것만 그린다 |
| `tests/` | `test_logic` 규칙 · `test_api` 라우트/저장 · `test_ui` 실제 브라우저 |

규칙을 `logic.py` 한 곳에 모으는 이유: 테스트가 서버를 안 띄우고 바로 부를 수
있고, 규칙이 바뀔 때 고칠 곳이 하나고, 화면과 API 가 서로 다른 숫자를 말하지
않는다.

## 환경변수

| | |
|---|---|
| `{{ENV}}_DB` | 저장 파일. **빈 문자열이면 아무것도 저장하지 않는다**(테스트) |
| `{{ENV}}_DATA` | 업로드·산출물 폴더. 저장을 끄면 여기도 꺼진다 |
| `{{ENV}}_PORT` | 포트 (기본 8000) |

## 이 골격이 미리 막아 둔 것

**설정을 모듈 최상단에서 읽지 않는다.** 파이썬은 같은 모듈을 두 번 임포트해도
처음 것을 돌려주므로, 전역에 박아 두면 나중에 환경변수를 바꿔도 옛 값이
살아남는다. 파일 하나만 돌리면 통과하고 전체를 돌리면 깨지는 테스트가 이래서
생긴다.

**테스트마다 상태를 되돌린다.** `tests/conftest.py` 가 환경변수와 메모리 상태를
매번 초기화한다. 앞 테스트가 남긴 것 때문에 순서를 바꿀 때만 깨지는 일을 막는다.

**순서를 매번 섞는다.** `pytest-randomly` 가 기본이라 격리가 깨지면 바로 드러난다.
고정 순서로 돌리려면 `pytest -p no:randomly`.

**화면은 브라우저로 확인한다.** 파이썬 테스트는 스크립트가 죽어도, 버튼이 아무
일도 안 해도 전부 통과한다. `tests/test_ui.py` 가 실제 Chromium 을 띄운다.

**워커는 하나만.** 상태를 메모리에 들고 있어서 여럿이면 서로 다른 메모리를 보고
덮어쓴다. 여러 워커가 필요해지면 그때 상태를 DB 로 완전히 내린다.
