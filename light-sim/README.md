# 실내 재배 공간 광 분포 시뮬레이터

화분을 어디에 두고 조명을 어디에 달지 정할 때, **배치를 바꾸면 각 화분이 받는 빛이
얼마나 달라지는지**를 계산한다. 식물끼리 서로 가리는 것까지 넣는다.

```
pip install numpy matplotlib pyyaml
python main.py config.yaml
python main.py config.yaml --compare config_alt.yaml
python main.py config.yaml --optimize          # 화분 배치를 다시 짠다
python main.py config.yaml --out 결과폴더
python validate.py config.yaml measured.csv   # 실측값과 맞춰 본다
pytest -q
```

## 나오는 것

- 화분별 **PPFD**(µmol/m²/s)와 **DLI**(mol/m²/day)
- **균일도 CV** = 표준편차/평균 (작을수록 고름)
- 격자 히트맵 PNG — 칸 안에 수치를 적는다
- 화분별 CSV (격자 좌표 + 실제 xy + 키·캐노피·LAI + PPFD·DLI)
- `--compare` 를 주면 두 배치를 같은 색 범위로 나란히 놓고 차이 패널을 하나 더 그린다

예시 두 설정은 **총 광량자속이 같다** — 1680 µmol/s 를 4등분(`기본배치`) 하느냐
2등분(`광원2개`) 하느냐만 다르다. 그래서 "조명을 몇 개로 쪼갤까" 가 그대로 비교된다.

```
[기본배치]  화분 50개  PPFD 평균 185.4  최소 119.4  최대 243.5  CV 0.156
[광원2개]   화분 50개  PPFD 평균 204.9  최소 110.6  최대 291.1  CV 0.212
[비교] 평균 PPFD +19.4   CV +0.056 (덜 고름)
```

광원을 적게 쓰면 평균은 오르지만(화분 쪽으로 더 몰려서) 고르기는 나빠진다.

## 배치 최적화 (`--optimize`)

키와 캐노피가 제각각이라 **누구를 어디에 놓느냐**로 차폐가 달라진다. 어느 화분을
어느 칸에 놓을지(순열)를 모의 담금질로 찾는다. 전수탐색은 화분 50개면 50! ≈ 3×10⁶⁴
가지라 논외다.

| | |
|---|---|
| 결정 변수 | 화분 → 격자 칸 배정 |
| 이웃해 | 격자 칸 둘을 골라 내용을 맞바꾼다 (빈 칸으로 옮기는 것도 같은 연산) |
| 목적함수 | `score = w_cv·CV + w_mean·(1/평균PPFD)`, **작을수록 좋다** |
| 판정 | 메트로폴리스 — 좋아지면 무조건, 나빠지면 `exp(-Δ/T)` 확률로 |
| 냉각 | 매 iteration `T ← T·cooling_rate` |

`optimize:` 블록에서 `w_cv` / `w_mean` / `initial_temp` / `cooling_rate` /
`iterations` / `seeds` 를 조정한다. `--seeds`, `--iterations` 로 덮어쓸 수 있다.

**초기 온도는 `0` 으로 두면 자동으로 잡는다.** 무작위 교환을 60번 해 보고
'평범하게 나빠지는 정도' 를 절반쯤 받아들이도록 `T₀ = 평균Δ/ln2` 로 맞춘다.
고정 숫자를 박으면 목적함수를 바꾸는 순간 무너지기 때문이다 — `w_mean` 을 키우면
점수가 통째로 다른 자릿수가 되고, `T₀` 가 낮으면 그냥 greedy 가, 높으면 끝까지
무작위 걷기가 된다.

가장자리는 광원에서 멀어 원래 어둡다. 거기에 키 큰 포기를 놓으면 수광점이 그만큼
위로 올라와 광원에 가까워지고, 대신 그 그늘은 이미 어두운 쪽으로 떨어진다.

**평균 PPFD 는 거의 안 움직인다(+0.8%).** 당연하다 — 재배치는 격자 위에서 빛을
나눠 갖는 방식만 바꿀 뿐 새로 만들어 내지 않는다. 그래서 `w_mean` 을 올려도 얻는
게 적다(`w_mean: 40` 으로 두면 평균 +0.1, CV 는 0.0763 → 0.0797 로 손해). 총량을
늘리려면 배치가 아니라 조명을 손대야 한다.

### 지역 최적 확인

시드를 바꿔 `seeds` 번 돌리고 CV 의 상대 표준편차를 본다. 2% 미만이면
"걱정 적음", 5% 미만이면 "대체로 일관", 그 이상이면 "iterations 를 늘리거나
initial_temp 를 올려 보라" 고 말해 준다. 예시 설정에서는 5개 시드가 전부
0.0763~0.0764 에 들어온다.

수렴 그래프에는 시드별 '여태 최고' 곡선과 함께 첫 시드의 **현재** 점수를 옅게
깐다. 최고 기록만 그리면 항상 예쁘게 내려가서 SA 가 실제로 언덕을 넘고 있는지
안 보인다 — 요동이 처음부터 없으면 온도가 너무 낮은 것이고, 끝까지 안 잦아들면
너무 높은 것이다.

## 실측 검증 (`validate.py`)

광량계를 몇 군데 대 보고 그 자리의 예측값과 맞춰 본다.

```
python validate.py config.yaml measured_example.csv
python validate.py config.yaml 측정값.csv --out 결과폴더 --worst 8
```

입력 CSV 는 첫 줄이 머리글이고 `#` 로 시작하는 줄은 건너뛴다. 좌표는 두 가지로
적을 수 있다:

| 열 | 뜻 |
|---|---|
| `x, y, z, ppfd` | 측정 지점의 실제 좌표(m)와 실측 PPFD |
| `row, col, z, ppfd` | 격자 칸으로 (화분 자리에서 쟀을 때) |
| `label` | (선택) 지점 이름. 없으면 `P1, P2, …` |

**격자 칸으로 적는 쪽을 권한다.** 화분 자리에서 재는 게 보통인데 그때마다 줄자로
xy 를 재면 그 자체가 오차가 된다. `row/col` 로 적으면 시뮬레이터가 쓰는 것과
같은 좌표 계산을 타므로 그 오차가 사라진다.

### 맞나 안 맞나보다 어떻게 틀리는지

하나의 점수로는 고칠 데를 못 찾는다. 그래서 편향·기울기·잔차 지도를 같이 낸다.

| 지표 | 읽는 법 |
|---|---|
| **R² (1:1 기준)** | `1 - Σ(예측-실측)²/Σ(실측-실측평균)²`. 회귀선을 새로 맞춘 r² 이 **아니다** — 그건 "비례하나" 만 보므로 모델이 전부 30% 낮아도 1.0 이 나온다. 음수면 실측 평균을 일괄로 쓰느니만 못하다는 뜻 |
| **RMSE / MAE** | RMSE 가 MAE 보다 크게 벌어지면 한두 지점이 크게 튄 것 |
| **편향** | 부호가 방향을 말해 준다. 음수 = 모델이 낮게 본다 |
| **맞춘 직선의 기울기** | `실측 = 기울기 × 예측 + 절편`. 1.2 면 "모델이 20% 낮게 본다" |
| **벽 거리 상관** | 잔차가 벽까지의 거리와 상관되는지 |

마지막 것이 이 스크립트의 핵심이다. **벽 반사는 Phase 1 이 통째로 빠뜨린
성분이고, 그 효과는 벽에 가까울수록 크다.** 오차가 벽 거리와 상관되면 원인이
좁혀진다 — 전체를 한 배율로 올려서 맞출 문제가 아니라 반사 모형을 넣어야 하는
문제라는 뜻이다.

### 예시 출력

`measured_example.csv` 는 **합성 데이터**다 (실제 측정값이 아니다). 모델값에 벽
반사 15~25% 와 잡음 2.5% 를 더하고, P7 한 곳만 모델이 모르는 그늘을 넣어 만들었다.

```
[검증] 측정점 12개
  실측 평균     203.6   예측 평균   176.7   µmol/m²/s
  R² (1:1)     -0.881   ← 음수 = 실측 평균을 쓰느니만 못하다
  RMSE           34.8   (실측 평균의 17.1%)
  평균절대오차    34.3   (MAPE 17.1%)
  편향           -27.0   (+ 면 과대평가)
  맞춘 직선    실측 = 0.610 x 예측 +95.9
  ※ 10개 지점은 캐노피 안/위라 그 화분은 차폐에서 뺐다.

[오차가 큰 지점]  상위 5개
  지점        x     y     z      실측     예측      오차
  P2        1.09  0.16  0.35    237.9    191.9    -46.0  -19.3%
  P7        1.31  0.60  0.35    176.0    220.1    +44.1  +25.1%   ← 유일하게 반대 방향
  ...

[읽기]
  - 모델이 전반적으로 13% 낮게 본다. Phase 1 은 벽·천장 반사가 없어 원래
    하한이라 예상된 방향이다 — 재배실 반사는 보통 10~30%다.
  - 오차가 벽 거리와 상관된다 (r=+0.67) — 벽에 가까운 지점일수록 더 모자란다.
    반사가 빠진 자리에 정확히 들어맞는 모양이라, 전체를 한 배율로 올려서는 안 맞는다.
```

넣어 둔 두 결함이 그대로 잡혔다. 반사 누락은 **편향 -13% + 벽 거리 상관 r=+0.67**
로, P7 의 인위적 그늘은 **혼자만 부호가 반대인 지점**으로 드러난다. 나머지가 전부
과소평가인데 P7 만 과대평가라는 게 신호다 — 전역 보정으로는 안 없어진다.

그림은 세 장이 한 판이다: 예측 대 실측 산점도(1:1 선과 맞춘 직선), **잔차 지도**
(실제 공간 좌표 위에 오차를 찍어 가장자리에서 밀리는지 광원 아래에서 밀리는지를
본다), 잔차 대 밝기. 오차가 큰 지점은 세 장 모두에 빨간 동그라미로 표시된다.

### 센서가 캐노피 위에 놓였을 때

광량계를 캐노피 꼭대기에 올리면 광원→센서 선분이 **제 원기둥 끝점**에 닿아
스스로를 가린 것으로 잡힌다. 그래서 센서가 얹힌(또는 안에 든) 화분은 차폐에서
뺀다 — `compute_ppfd` 가 화분 자신을 빼는 것과 같은 이유다. 옆 화분은 그대로
센다. 몇 개 지점이 여기 해당했는지 출력에 적어 준다.

## 계산 모델

| | |
|---|---|
| 광원 | 아래를 보는 **램버시안** 배광 `I(θ)=I₀cosθ`, `beam_angle` 밖은 0 |
| 정규화 | 반각 θₘ 원뿔 안에서 `Φ=I₀·π·sin²θₘ` → `I₀ = ppf/(π sin²θₘ)` |
| 수광 | `E = I₀·cos²θ / d²` (역제곱 × 램버트 코사인 법칙) |
| 수광점 | 캐노피 **상단 중심** — 잎이 가장 많이 받는 지점 |
| 상호 차폐 | 캐노피를 반지름 `canopy_radius`, 높이 `plant_height` 인 **원기둥**으로 보고, 광원→수광점 선분이 지나면 투과율을 곱한다 |
| 투과율 | 비어–람베르트 `τ = exp(-k·LAI)`, 기본 `k=0.7` |
| 합산 | 광원끼리 간섭 안 하므로 단순 합 |

**Phase 1 이라 벽·천장 반사는 없다.** 실제 재배실은 반사로 10~30% 가 더 들어오므로
여기 값은 보수적인 하한으로 읽어야 한다. CFD·환기·온도도 다루지 않는다.

화분은 **자기 자신을 가리지 않는다** — 수광점이 제 캐노피 꼭대기라 자기 원기둥과는
끝점에서 만나고, 그걸 세면 온 격자가 균일하게 어두워지기만 한다.

## 좌표계

미터, 오른손. `x` = 폭(col 방향), `y` = 깊이(row 방향), `z` = 위(바닥이 0).
격자는 공간 한가운데 놓이므로 화분은 `grid_position: [row, col]` 만 적으면
실제 xy 는 격자 간격에서 나온다 — 간격 하나만 바꿔도 배치 실험이 된다.

## 테스트

차폐 판정(3차원 선분 대 유한 원기둥)은 눈으로 검산이 안 되고, 틀려도 PPFD 는
그럴듯한 숫자로 나온다. 그래서 손으로 답을 아는 경우를 박아 뒀다 — 안 가림 /
정면 차폐 / 광원 바로 아래 / 반지름을 1 mm 차이로 스치는 경계 / 수광점 너머.

물리 쪽 검산은 **광량자속 보존**이다. 바닥 전체를 수치적분하면 광원이 낸 ppf 가
그대로 돌아와야 한다 (`test_the_floor_gets_back_every_photon_the_lamp_emitted`).
비율만 보는 테스트는 절대값이 통째로 틀려도 다 통과하므로, 정규화가 맞는지는
이 하나가 잡는다.

```
1000.0 µmol/s 방출 → 1000.0 µmol/s 회수 (100.00%)
```

SA 는 무작위라 "정답" 을 박을 수 없다. 대신 **어겨서는 안 되는 성질**을 건다:
화분이 사라지거나 늘지 않을 것, 한 칸에 둘이 겹치지 않을 것, 같은 시드면 같은
답일 것, 시작 배치보다 나빠지지 않을 것. 이게 깨지면 점수가 아무리 좋아도 실제로
놓을 수 없는 배치다.

최적화는 속도 때문에 `compute_ppfd_fast`(numpy 배열판)를 쓴다 — 반복문판은 한 번에
6 ms 라 5시드 × 6000 iteration 이 3분이 된다. 둘이 조용히 갈라지면 엉뚱한 배치를
고르게 되므로, 무작위 배치 12개로 매번 자릿수 12자리까지 맞춰 본다. 최종 보고
수치는 다시 참조 구현(`compute_ppfd`)으로 낸다.
