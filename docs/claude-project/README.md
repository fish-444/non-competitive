# 클로드 프로젝트에 붙여넣을 파일들

claude.ai 의 **프로젝트(Projects)** 에 이 저장소를 물려 두면, 매번 코드를 설명하지
않고도 이어서 일할 수 있다. 이 폴더는 그때 **붙여넣을 것들**이다.

## 어디에 무엇을 붙이나

| 파일 | 붙일 곳 | 왜 |
|---|---|---|
| `0-지침.md` | 프로젝트 **지침**(Instructions) 칸 | 짧아야 하는 칸이다. 매 대화에 항상 들어가므로 규칙만 담았다 |
| `1-개요와-규칙.md` | 프로젝트 **지식**(Knowledge) | 무엇을 만드는 앱이고, 무엇을 지켜야 하나 |
| `2-구조와-데이터.md` | 프로젝트 **지식** | 파일이 어떻게 나뉘고 값이 어떻게 흐르나 |
| `3-API.md` | 프로젝트 **지식** | 엔드포인트와 응답 필드 |
| `4-설계원칙과-함정.md` | 프로젝트 **지식** | 이 저장소가 실제로 데어 본 것들 |

지식 칸은 파일을 올려도 되고 본문을 붙여 넣어도 된다. **`0-지침.md` 만은 지침
칸에 넣어야** 매 대화에 자동으로 붙는다.

## 한 번에 붙이고 싶으면

합친 파일을 따로 만들어 두지 않았다. 두 벌이 되면 반드시 갈라지기 때문이다
(이 저장소가 `first-contributions` 사본에서 겪은 그대로다). 필요할 때 만들어 쓰자.

```bash
cd docs/claude-project
cat 1-*.md 2-*.md 3-*.md 4-*.md > /tmp/전체.md
```

## 코드가 바뀌면

이 문서들은 **손으로 쓴 요약**이라 코드를 고쳐도 저절로 안 따라온다. 아래가
바뀌면 같이 손봐야 한다.

- 모듈이 늘거나 의존 관계가 바뀜 → `2-구조와-데이터.md`
- 엔드포인트·응답 필드가 바뀜 → `3-API.md`
- 새로 데인 함정이 생김 → `4-설계원칙과-함정.md`
- 테스트 개수 → `1-개요와-규칙.md` (지금 450개)

## 이 폴더에 넣지 말 것

`farm_env.bat` / `farm_env.sh` 의 내용, `farm.db`, `bench_data/` 는 **절대 넣지
않는다.** 프로젝트 지식은 대화마다 모델에게 그대로 넘어간다 — 키가 한 번 새면
폐기해야 한다(이 저장소는 실제로 겪었다).
