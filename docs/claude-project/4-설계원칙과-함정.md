# 4. 이 저장소가 실제로 데어 본 것들

전부 겪고 나서 정한 것이다. 새 기능을 붙일 때 같은 자리에서 다시 데지 않으려면
이 목록을 먼저 본다.

## 정직성 — 사람이 이 숫자를 믿고 실제로 물을 준다

### 모르면 숫자를 만들지 않는다

`harvest.py` 가 지키는 선이 그대로 본보기다.

| 이럴 때 | 이렇게 말한다 |
|---|---|
| 측정 1회 / 사흘도 안 벌어짐 | "아직 속도를 못 냅니다 — 며칠 뒤 다시 스캔해 주세요" |
| 기울기 ≤ 0 | "포기가 안 커지고 있어요 — 빛·물·자리를 살펴 주세요" (실패가 아니라 **신호**다) |
| 이 속도면 120일 넘게 | "날짜를 찍기엔 너무 멉니다" |
| 이미 기준 크기 넘김 | "지금이 수확적기예요" (기울기 없이도 답한다) |

근거 없는 날짜가 달력에 박히면 사람은 그걸 믿고 준비한다. **"아직 모름"이 낫다.**

### 추정을 측정처럼 말하지 않는다

- 열매는 탐지가 **안 된다**(모델은 잎·캐노피만 본다). 딸기·토마토·고추 생산량은
  포기 크기로 에두른 추정이라 `rough` 로 표시하고 화면에 `(어림)` 이라 적는다.
  잎채소는 잎을 실제로 세니 그 표시가 없다.
- Open-Meteo 의 토양수분·지온은 **노지 격자의 흙**이다. 화면에 `바깥 흙 수분` 으로
  띄우고 "화분 상토와는 다릅니다"를 같이 적는다. **물주기 계산에는 안 넣는다.**

### 잠정값은 잠정값이라고 적는다

작물별 물주기 간격·수확 규격·광량 배수는 원예 통념에서 잡은 값이라 `provisional`
로 표시돼 있다. 실제 재배 기록이 쌓이면 그 값으로 간다.

### 설정을 안 건드린 사람에게는 아무것도 안 바뀐다

새 기능의 기본값은 늘 '예전 그대로'다.

- 작물을 안 고르면 알로카시아 → 물·등급·광량이 예전과 같다.
- 위치를 안 넣으면 기상 기능이 꺼져 있고, 넣어도 기본(실내)은 반영 0%.
- `watering.plan_interval(..., weather_days=0.0)` · `harvest.forecast(..., growth_factor=1.0)`
  — 인자를 안 주면 예전 값이 그대로 나온다. 테스트로 고정해 뒀다.

## 계산에서 데인 것

### 이중 계산 — 절대값이 아니라 편차로 쓴다

| 하마터면 | 왜 틀리나 | 그래서 |
|---|---|---|
| ET0 절대값을 물주기에 곱함 | 작물별 달별 간격이 **이미 계절성**을 담고 있다(서울 달별 ET0 와 상관 r≈0.95) | **평년 대비 편차**만 얹는다 |
| 적산온도(GDD)를 생장 기울기에 곱함 | 기울기는 그 온실에서 실제로 찍은 사진에서 나온 값이라 **겪은 온도가 이미 들어 있다** | **잰 기간 대비 앞으로**의 비율만 쓴다 |

### 보정이 규칙을 우회하면 안 된다

`harvest` 의 두 거절("안 자란다", "너무 멀다")은 날씨 배율을 곱하기 **전** 실측
기울기로 판정한다. 날씨가 좋아진다고 원래 안 나왔을 날짜가 나오면 보정이 아니라
우회다. 테스트 두 개가 이걸 지킨다.

### 마지막 두 점의 차이가 아니라 기울기

탐지는 사진마다 들쭉날쭉하다. 잎이 가려져 캐노피가 1cm 작게 잡힌 날 하나가 마지막
점이면 두 점 차이로는 "줄어들었다"가 되고 수확적기가 통째로 뒤집힌다. 최소제곱
기울기를 쓰면 그 튐이 묻히고, r² 로 **신뢰도까지 말할 수 있다**.

### 강수는 노지에서만

지붕 아래 화분에는 비가 한 방울도 안 떨어진다. "어제 비 왔으니 물주기 미룸" 은
관수 서비스가 흔히 하는 계산인데, 여기서는 장마철 내내 물을 밀어 화분을 말린다.

### 화분에 안 맞는 데이터는 아예 안 붙인다

흙토람(농진청) 토양정보를 검토했다가 뺐다 — 조회에 19자리 PNU(지번코드)가 필요해
집 주소를 받아야 하고, 얻는 건 **그 필지 땅의 성질**이지 화분 상토가 아니다.
화면에 'pH 6.9 / 배수 양호'가 뜨면 사용자는 앱이 자기 화분을 쟀다고 믿는다.

## 설정에서 데인 것

### import 순서 (`main.py`)

우리 모듈(`crops` `harvest` `placement` `providers` `watering` `weather`)의 import 는
`_load_env_file()` **뒤**에 있다. 위로 올리면 모듈 최상단 `os.environ.get()` 이
farm_env 를 읽기 전에 돌아 값이 굳는다. `set CONFIDENCE=15` 가 오랫동안 아무 효과가
없던 게 이것이다. 새 환경변수도 같은 함정에 빠진다.

### 키 넣다가 나는 실수 세 가지

| 실수 | 증상 | 앱의 대응 |
|---|---|---|
| `set KEY="값"` (파워셸 습관) | 배치는 **따옴표까지 키 값**으로 쓴다 | 걷어내고 `[키 경고]` 출력 |
| 붙여넣을 때 줄 끝 공백 | 401 | 걷어내고 경고 |
| 폐기한 옛 키 | `This API key does not exist` | 앞 4자리를 찍어 대조하게 함 |

`_load_env_file()` 은 `farm_env.bat` 을 찾으면 거기서 멈춘다 — bat 과 sh 가 둘 다
있으면 sh 는 안 읽힌다. `_ensure_env_file()` 은 파일이 **없을 때만** 만드니,
템플릿에 새 키 줄을 넣어도 **이미 설치한 사용자에게는 안 간다**(README 로 안내해야 한다).

### 기상청 API 함정 (`providers/weather_kma.py`)

셋 다 조용히 빈 응답으로만 나타난다.

1. **발표시각 단위가 오퍼레이션마다 다르다** — 초단기실황 `HH00`(40분 이후),
   초단기예보 `HH30`(45분 이후), 단기예보 하루 8회 `0200·0500…2300`(10분 이후).
2. **KST 기준** — 서버가 UTC 면 9시간 어긋나 매번 엉뚱한 발표를 조회한다.
   00:00~02:09 에는 **전날 2300** 으로 돌아가야 한다.
3. **`numOfRows` 기본값이 10** — 단기예보는 한 번에 700건이 넘어 조용히 잘린다.
   오류가 아니라 정상 200 이라 더 위험하다.

덧붙여 `PCP`/`RN1` 은 `강수없음` `1.0mm 미만` `30.0~50.0mm` 같은 **한글 범주**로 온다.
`float()` 로 바로 캐스팅하면 비 오는 날 터진다. `±900` 은 결측 마스킹이다.

## 측정에서 데인 것

### 그룹화는 규칙대로 돌면서도 틀릴 수 있다

그럴듯해 보이는 규칙(중복 캐노피 정리, 잎과 같은 박스인 캐노피 제거)을 넣었다가
`bench_real.py` 가 더 나빠져서 되돌렸다. **그룹화를 건드렸으면 재고 나서 말한다.**

### 잎 한 장은 포기 크기를 대표하지 못한다

큰 잎 한 장만 달린 어린 포기와 같은 크기 잎이 여덟 장 달린 다 큰 포기가 같은 등급이
돼 버린다. 그래서 등급은 **캐노피(포기 전체 폭)** 로 매기고, 캐노피를 못 잡았을 때만
가장 큰 잎으로 물러난다.

### 사진 구도에 휘둘리던 것

- 화면 대비 비율로 등급을 매기던 시절엔 같은 식물도 가까이 찍으면 대품, 멀리서
  찍으면 소품이었다 → **선반 네 모서리(`CALIB`)로 cm 배율**을 잡는다.
- 카메라에서 먼 자리는 작게 찍힌다 → 자리별 거리 보정(`_distance_gain`). 단
  **한 장 탑뷰에서만** 켠다(여러 장은 카메라 위치가 달라 성립하지 않는다).

## 화면에서 데인 것

- 크기 등급을 손으로 바꿔도 `top_leaf_size` 를 같이 안 바꾸면 **3D 는 그대로**라
  "고쳤는데 반영이 안 된다"가 된다. 두 필드는 다르다.
- 데모 모드(키 없음)는 사진과 무관한 난수를 뱉는다. 작은 라벨로는 그냥 지나쳐서
  (실제로 그 상태로 탐지 품질을 여러 번 판단했다) **눈에 띄는 경고 상자**를 띄운다.
- 모달과 달력이 서로 다른 날짜를 말하면 안 된다 — 물주기 보정은
  `recommend()` 와 `upcoming()` **양쪽에** 같은 값이 들어가야 한다.
